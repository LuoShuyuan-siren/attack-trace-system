# 组内测试数据说明

本文档依据当前目录中的实际文件整理，说明新一轮 `TC001` 至 `TC008` 测试的目的、数据来源、文件用途和证据边界。以下路径均相对于本文档所在的 `docs/testbed/` 目录。

## 使用边界

- `TC001` 至 `TC008` 是八个独立测试样本，不代表已经形成一条连续攻击链。
- 关联不同主机数据时，应同时核对日志内部时间、源 IP、目标 IP、端口、进程和事件 ID，不能只依据文件修改时间或目录名称。
- Windows 防火墙日志和 EVTX 多为时间窗口内的原始日志快照，可能包含其他时段或旧网段流量，不能把整份文件无条件归因于当前测试。
- `初次基础测试文件/` 是早期资料，不属于本轮 `TC001` 至 `TC008` 数据，本文不列出也不修改该目录。
- 本文只说明原始数据和测试记录，不把原始文件直接写成系统的 `NormalizedEvent`、`DetectionResult` 或正式攻击结论。

## 统一取用说明

| 数据类型 | 取用位置 | 主要用途 |
| --- | --- | --- |
| Kali 网络流量和命令输出 | 各测试目录下的 `kali-TC.../` | 网络解析、命令结果和测试时间核对 |
| Windows 主机日志 | 各测试目录下的 `win11-TC.../` | Windows EVTX、Sysmon、防火墙和测试时间分析 |
| Ubuntu 服务或认证数据 | 各测试目录下名称含 `ubuntu` 的目录，或 TC003/TC004 根目录的服务端日志 | Web、SSH、C2 和接收端证据分析 |
| 完整性记录 | `sha256.txt`、`SHA256SUMS.txt`、`SHA256SUMS-ubuntu.txt` | 校验采集文件是否发生变化 |

目录名称中的 `kali`、`win11`、`ubuntu` 仅表示数据来源或承载角色，不表示本目录额外增加了虚拟机。三台虚拟机承担多个逻辑服务角色的说明见 `topology.md`。
