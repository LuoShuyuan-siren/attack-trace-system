## 1. 已实现功能总览

### 1.1 Parser（解析器层）— `backend/app/parsers/traffic/`

| 模块 | 文件 | 功能 |
|------|------|------|
| `PcapParser` | `pcap_parser.py` | PCAP/PCAPNG 经典格式 + EPB 块；Ethernet / Raw IP / Linux SLL 三种链路层；IPv4 / IPv6 头；TCP/UDP/ICMP/DNS/HTTP 协议字段提取；支持目录批量解析 |
| `ZeekParser` | `zeek_parser.py` | Zeek TSV 日志：conn.log / dns.log / http.log / ssl.log；自动日志类型检测（文件名→#path→#fields 三级）；`-` 空值容错；支持目录批量解析 |
| `SuricataParser` | `suricata_parser.py` | Suricata eve.json：flow / dns / http / alert / tls 五类事件；Suricata severity 1/2/3 → high/medium/low 映射；损坏 JSON 行容错；未知类型跳过 |

**3 个 Parser 全部基于 `BaseParser` 抽象类实现，统一签名 `parse(source: Path) -> list[NormalizedEvent]`，`source_type = "network_traffic"`。**

### 1.2 Analyzer（分析器层）— `backend/app/analyzers/traffic/`

| 模块 | 文件 | 检测能力 |
|------|------|---------|
| `DnsAnalyzer` | `dns_analyzer.py` | ① 高频查询 ② 异常长域名 ③ 子域高熵 ④ 大量唯一子域 ⑤ TXT 异常 ⑥ NXDOMAIN 比例 ⑦ DNS 隧道综合判定（score ≥ 3 触发，≥ 5 升级 high） |
| `HttpAnalyzer` | `http_analyzer.py` | ① 异常长 URI ② URI 高熵 ③ 可疑 UA（8 个关键词） ④ 大上传 ⑤ 高 POST 频率 ⑥ Beacon 周期性 ⑦ HTTP 隐蔽信道综合判定 |
| `IcmpAnalyzer` | `icmp_analyzer.py` | ① 高频 ICMP ② 大 payload ③ payload 长度稳定 ④ payload 高熵 ⑤ 周期性 ⑥ 双向通信 ⑦ ICMP 隧道综合判定 |
| `ConnectionAnalyzer` | `connection_analyzer.py` | ① 端口扫描 ② 大范围连接 ③ 非常用端口（23 个白名单） ④ 长连接（>1h） ⑤ Beacon 周期性连接 ⑥ 高频连接 |

**4 个 Analyzer 全部基于 `TrafficAnalyzerBase`（继承 `BaseAnalyzer`）实现，统一签名 `analyze(events: list[NormalizedEvent]) -> list[DetectionResult]`。**

## 3. 已知限制

### 3.1 PcapParser

| 限制 | 说明 |
|------|------|
| **PCAPNG 仅支持 Enhanced Packet Block (EPB, type=6)** | Interface Description Block (IDB, type=1) 用于读取 if_tsresol；Simple Packet Block (SPB, type=3)、Section Header Block (SHB) 的部分高级特性未实现。对于常见抓包与测试场景足够 |
| **支持的链路层有限** | Ethernet (1) / Raw IP (101) / Linux SLL (113)；802.11 无线、Linux SLL2、用户态 DLT 等未支持 |
| **IPv6 高级特性未解析** | 仅识别 40 字节基础头 + next header；扩展头按 `next_header` 递归级别有限 |
| **DNS 解析仅 UDP/TCP 53 端口启发式** | 非标准端口 DNS over HTTPS/TLS 等未识别 |
| **HTTP 解析仅 payload 启发式** | 不解析 TLS 加密流量内的 HTTP；payload 截断 200 字符 |

### 3.2 ZeekParser

| 限制 | 说明 |
|------|------|
| **支持的日志类型有限** | 已实现：conn.log / dns.log / http.log / ssl.log。**未实现**：files.log / notice.log / weird.log / dhcp.log / conn-summary.log / software.log 等 Zeek 全部日志类型 |
| **依赖 TSV 头解析** | 需要日志包含 `#fields` 头；缺失头时按 fallback 处理但成功率有限 |
| **未实现流重组** | 单条日志独立处理，不做跨日志流重组 |

### 3.3 SuricataParser

| 限制 | 说明 |
|------|------|
| **支持的事件类型有限** | 已实现：flow / dns / http / alert / tls。**未实现**：anomaly / fileinfo / ftp / smtp / ssh / stats / drop 等其他 eve.json 类型（未知类型静默跳过） |
| **alert 事件的 payload 字段** | 原样存入 `raw_data["payload"]`，未做 base64 解码或大小限制 |
| **依赖 JSON Lines 格式** | 单行一个 JSON 对象，不支持紧凑 JSON 数组格式 |

### 3.4 Analyzer 共用

| 限制 | 说明 |
|------|------|
| **时间窗口为全量统计** | 速率/周期性/Beacon 计算基于事件全集，未做真正的滚动时间窗口分段聚合 |
| **置信度公式简单** | `base + score × increment` 线性递增，未考虑证据多样性、上下文权重等复杂因素 |
| **告警去重** | 同一攻击事件可能产生多条 DetectionResult（如 HTTP Beacon + 高频请求），调用方需自行去重 |
| **ATT&CK 映射简化** | 仅在明确技术（DNS 隧道 T1071.004、HTTP Beacon T1071.001、端口扫描 T1046、ICMP 隧道 T1571.004）时设置 `attack_technique_id`；广义 beacon/异常行为未做完整 ATT&CK 矩阵映射，留给成员6 |

### 3.5 检测算法

| 限制 | 说明 |
|------|------|
| **周期性检测为单维度** | 仅基于间隔变异系数 CV；未实现频谱分析、自相关函数等更稳健的检测方法 |
| **不检测应用层 payload 模式** | 不做 SQL 注入、XSS 等 WAF 层面检测（属其他成员职责） |
| **不维护主机/会话状态** | 无持久化跨事件状态，所有分析在单次 `analyze()` 调用内完成 |
